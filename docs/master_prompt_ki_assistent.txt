Projekt-Beschreibung & Features:
Wir bauen ein Tool zur Verwaltung von Immobilien und deren Finanzen. Es geht um echte, private Finanzdaten meiner Eltern - Sicherheit hat oberste Priorität. Die App ist eine Vorbereitung für den Steuerberater, kein Steuerberater-Ersatz.
* Immobilien-Verwaltung: Speichern von Stammdaten (Kaufpreis inkl. Aufteilung Grund/Gebäude, Rechtsform wie GbR/GmbH/Privat).
* Kennzahlen-Dashboard: Anzeige von monatlichen Kosten, Mieteinnahmen, Abschreibung (AfA), Mietrendite und Marktwert.
* Beleg-Erfassung (KI-gestützt): Upload von Rechnungen/Belegen (in Firebase Storage). Die Gemini API liest diese aus, extrahiert Betrag, Datum, Verwendungszweck und schlägt eine Kategorie + Datenbank-Eintrag vor. Der Nutzer muss nur noch prüfen und bestätigen.
* Jahresabschluss: Berechnung einer Einnahmen-Überschuss-Rechnung (EÜR) pro Immobilie, exportierbar als CSV/PDF. Fokus zunächst auf Rechtsform Privat/GbR.
* Geräteübergreifend: Da Firebase genutzt wird, muss die Web-App auf Desktop und Mobile (Browser) funktionieren und Daten in Echtzeit synchronisieren.

Wichtige technische Grundregeln (immer beachten):
1. Zugriff nur für erlaubte E-Mails (feste Whitelist: ich + meine Eltern) - erzwungen über Firestore Security Rules, nicht nur im Frontend.
2. Firestore Security Rules sind Pflicht: Zugriff serverseitig prüfen, nie nur im Client.
3. Geldbeträge immer als Ganzzahl in Cent speichern (z.B. 120050 = 1.200,50 €), niemals Fließkommazahlen für Geld.
4. Gemini API-Key niemals im Browser - alle KI-Aufrufe laufen über eine Server Action / Route Handler, Key liegt in .env.
5. Früh und oft auf Vercel deployen - schon ab Phase 1.

Datenmodell (Firestore), user-scoped:
* properties: Kaufpreis (Cent), Aufteilung Grund/Gebäude, Rechtsform, Adresse, Kaufdatum.
* transactions: Betrag (Cent), Datum, Verwendungszweck, Kategorie (feste Liste), Verknüpfung zu Immobilie + optional Beleg.
* documents: Storage-Pfad, Dateiname, Upload-Datum, verknüpfte Transaktion, von Gemini extrahierte Rohdaten.
